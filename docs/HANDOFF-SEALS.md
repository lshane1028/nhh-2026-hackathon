# 낙관(seal) 시각화 — 인수인계

## 상태

**데이터는 다 있고, 그림만 없다.**

- `card.seal`은 `"yellow" | "red" | "blue" | "purple"` 중 하나로 세팅되고, 저장되고, 엔진이 읽는다
- 호버 패널에 `낙관 · 적인`처럼 이름은 나온다
- 카드 앞면에는 **아무것도 안 그린다**

두 번 만들었고 두 번 다 반려됐다. 세 번째 시도로 반쯤 고치는 것보다 지우고 넘기는 게 낫다고 판단해서, 코드에서 시각 부분을 전부 걷어냈다. 백지에서 시작하면 된다.

## 붙이는 자리

`app/components/card-visuals.ts`의 `getCardMarks()`에 이것만 추가하면 렌더까지 이어진다.

```ts
if (card.seal) {
  marks.push({
    id: `seal-${card.seal}`,
    slot: "bottom-right",   // 이미 비워 둔 자리
    sprite: /* MarkSprite */,
    fill: /* 색 */,
    label: SEAL_LABELS[card.seal],
    detail: `낙관 · ${SEAL_LABELS[card.seal]}`,
  });
}
```

`SEAL_LABELS`는 같은 파일에 남아 있다. `.hwatu-card__mark--bottom-right` 자리도 `game-ui.css`에 비워 뒀다 — 효과 태그가 그리로 넘어오지 못하게 막아 둔 것이다.

스프라이트를 쓸 거면 `CardMark.tsx`의 `MarkSprite`에 이름을 추가하고 12×12 ASCII 지도를 넣으면 된다(`.` 투명 / `X` 본체 / `o` 외곽 / `+` 하이라이트). 스프라이트를 안 쓰고 다른 방식으로 그려도 된다 — `getCardMarks`를 안 쓰고 `HwatuCard.tsx`에 전용 레이어를 하나 더 넣는 쪽이 더 자유롭다.

## 지켜야 하는 제약

이건 취향이 아니라 이미 실패해서 알아낸 것들이다.

**1. 우하단을 벗어나지 말 것.** 네 범주가 각자 채널을 하나씩 갖는다.

| 채널 | 무엇을 답하나 | 어디 | 범주 |
| --- | --- | --- | --- |
| 재질 | 무엇으로 만들어졌나 | 면 전체 | 각인 8종 |
| 표면 | 빛을 어떻게 받나 | 면 전체 문양 | 판본 4종 |
| 물건 | 무엇이 붙어 있나 | **우하단** | **낙관 4종** |
| 물건 | 무엇을 지니고 있나 | 좌중단 | 효과 태그 12종 |

좌상단은 월 배지가 쓴다. 네 개가 한 장에 다 붙는 카드가 실제로 나오므로 자리를 옮기면 반드시 겹친다.

**2. 밝은 획과 어두운 획을 같이 넣을 것.** 화투패는 크림과 먹이 둘 다 크게 있다. 밝기만 있는 그림은 크림 위에서, 어둡기만 한 그림은 먹 위에서 사라진다. 반드시 두 톤을 다 가질 것.

**3. 속을 채울 것.** 첫 시도가 속 빈 사각 테두리였는데, 이 크기에서는 작은 빈 상자로 읽혔다. 밀랍 도장은 물건이지 선 그림이 아니다.

**4. 크게.** 두 번째 시도에서 카드 폭 38%까지 키웠다. 발라트로 인장이 안 봐도 눈에 들어오는 건 순전히 크기와 채움이다. 29%는 아이콘으로 읽혔다.

**5. 이미 쓰고 있는 기하를 피할 것.** 목판화에는 기하학이 없어서 기하 문양이 잘 읽히는데, 그래서 열두 개가 이미 자리를 잡고 있다.

| | | | |
| --- | --- | --- | --- |
| 먹칠 | 잉크 경계선 | 금전패 | 원(구멍 뚫린 엽전) |
| 홍칠 | 3° 가로 붓결 | 복패 | 0° 주사선 + 찢김 |
| 만능화 | ±58° 격자 | 금박 | 흩뿌린 조각 |
| 유리패 | 122° 사선 | 자개 | 동심원 |
| 강철패 | 90° 세로결 | 오방색 | 118° 다섯 띠 |
| 돌패 | 금 + 반점 | 음각 | 96° 홈 |

**동그라미 계열은 이미 셋이다**(금전패·자개·금박). 낙관을 원형 밀랍으로 가면 그 넷째가 된다 — 크기와 채움이 확실히 다르면 될 수도 있지만, 각진 도장 쪽이 안전하다. 한국 낙관은 원래 네모난 전각이기도 하다.

**6. 색은 화투 팔레트 안에서.** `#c2352a` 빨강 · `#e0ad45` 금 · `#2c2622` 먹 · `#2f7a63` 비취 · `#3a5f8a` 쪽 · `#7a3f74` 자주. 네 낙관은 황·적·청·자라 금·빨강·쪽·자주에 그대로 대응된다.

**7. 도트로 그릴 것.** 카드 그림이 도트라, 매끈한 벡터에 한자를 얹으면 다른 게임에서 가져다 붙인 것처럼 보인다. 이건 실제로 반려된 첫 번째 버전이다.

## 확인 방법

`card-effects-check.html`을 파일에서 그냥 열면 된다. 빌드도 서버도 필요 없고, 진짜 `game-ui.css`와 진짜 카드 이미지를 읽는다. 맨 아래 "겹쳐도 보이나" 구역에 수식어가 2·3·4개 붙은 카드가 있다.

**혼자 있을 때만 읽히는 건 해결한 게 아니라 피한 것이다.** 4개짜리에서 낙관이 보이는지가 통과 기준이다.

숫자로도 볼 수 있다. 카드의 세 바탕색(크림 `247,240,223` / 먹 `20,17,15` / 주 `200,45,30`)에 합성 수식을 직접 돌려서, 어느 하나에서도 안 사라지는지 재면 된다. 지금까지 실패한 다섯 개가 전부 이 검사에서 한 자릿수가 나왔다.

## 참고 — 왜 이렇게까지 까다로운가

발라트로는 강화·인장·에디션 셋이 겹쳐도 읽힌다. 배지를 잘 그려서가 아니라 셋이 **카드에 대한 다른 물리적 사실**이라서다. "유리로 만들어졌다", "밀랍이 붙어 있다", "빛난다"는 서로 다른 질문의 답이라 같은 픽셀을 두고 다투지 않는다.

우리는 범주가 넷이라 발라트로보다 한 겹 어렵다. 그래서 자리와 채널을 고정해 뒀고, 그 규칙만 지키면 나머지는 자유롭게 해도 된다.
