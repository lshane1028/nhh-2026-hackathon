# 경화수월 UI·아트 바이블

최종 갱신: 2026-08-12

이 문서는 새 카드·화면·이펙트를 추가할 때 지켜야 할 시각 기준입니다. 기존 화면을 전면 재작성하는 지침이 아니라, 이미 확립된 먹색·주홍·금박·한지 방향을 수치로 고정해 회귀를 막는 기준입니다.

## 1. 핵심 인상

- 바탕: 먹빛 칠기와 짙은 녹색 놀이판
- 정보 면: 누렇게 바랜 한지, 밝은 아이보리는 작은 정보 카드 안에서만 사용
- 강조: 주홍은 행동·위험, 청록은 합·칩, 금빛은 보상·희귀도·최종 결과
- 질감: 종이결과 칠기결은 낮은 대비로 유지하고 글자 뒤에서는 밀도를 낮춤
- 조형: 현대 유리 패널보다 목판, 족자, 책등, 제단, 낙관의 실루엣을 우선

## 2. 불변 치수

| 요소 | 기준 |
| --- | --- |
| 화투패·부적·비결서·금단장 | 기본 2:3 |
| 카드 원화 안전 영역 | 네 변 2px 이상, 월 숫자와 종류 표식을 침범하지 않음 |
| 카드 이미지 맞춤 | `object-fit: contain`; `cover` 금지 |
| 카드 모서리 | 원화와 효과 레이어가 같은 반경을 공유 |
| 툴팁 | `document.body` 포털, viewport 네 변에서 12px 이상 여백 |
| 모바일 가로 | `100dvh`, safe-area inset, 2:3 비율 유지 |
| 터치 목표 | 최소 44×44 CSS px |

11·12월과 검은 면이 큰 패는 별도 예외가 아닙니다. 다른 달과 같은 프레임과 `contain` 규칙을 사용하고 원화 자체를 자르지 않습니다.

## 3. 카테고리 실루엣

- 부적: 세로 족자·부적지. 작은 상태에서도 위아래 축과 종이 외곽이 보여야 함.
- 비결서: 책등·실 제본. 닫힌 책의 두께와 매듭을 유지.
- 금단장: 검은 제단·의식구. 가장 어둡되 이름과 대가 표시는 읽혀야 함.
- 화공패: 붓·안료·공방 도구. 카드 변형이라는 기능이 그림만으로 암시되어야 함.
- 팩: 주머니나 함. 후보 수가 달라도 같은 계열 실루엣을 공유하고 크기 표시는 UI가 담당.

## 4. 강조 예산

1. 상시 반짝임: 판본·재질 카드에만 허용.
2. 짧은 강조: 선택, 드로우, 버리기, 수집 착지.
3. 중간 강조: 개별 카드 득점, 부적 발동, 금단장 결과.
4. 큰 강조: 높은 족보, 보스 월 진입, 계절 계약, 최종 승리.

낮은 단계가 높은 단계보다 더 큰 화면 섬광·더 긴 정지·더 많은 입자를 사용하면 안 됩니다. `prefers-reduced-motion`에서는 이동량과 반복만 줄이고 결과 정보는 남깁니다.

## 5. 계절 이펙트

- 봄: 꽃잎. 크기·회전·초점이 다른 3개 깊이층.
- 여름: 빗줄기와 물비늘. 화면 전체 흰 선 대신 판 가장자리와 광택에 집중.
- 가을: 단풍과 마른 잎. 큰 잎은 느리게, 작은 잎은 빠르게 흘림.
- 겨울: 서리 결정과 입김. 카드 글자 위에 불투명한 흰 막을 만들지 않음.

작은 사각 파티클 수를 늘리는 방식보다 계절별 큰 실루엣과 깊이 차이를 우선합니다.

## 6. 승인용 회귀 조합

시각 변경은 아래 조합을 함께 확인해야 합니다.

1. 11월·12월 카드가 같은 손에 있고 둘 다 선택된 화면
2. 검은 면이 큰 카드에 각인·판본·낙관·효과가 동시에 붙은 화면
3. 부적 5개와 긴 툴팁이 열린 1366×768 화면
4. 장터 상품이 최대 수량으로 나온 1366×768 화면
5. 제출 연출과 실제 왼쪽 수집 착지가 동시에 보이는 화면
6. 844×390, 915×412 모바일 가로 화면
7. `prefers-reduced-motion` 상태의 보스 월과 높은 족보 연출

## 7. CSS 변경 규칙

- 현재 import 순서 `game-ui → game → art-direction → pixel-direction`의 시각 결과를 보존합니다.
- 새 화면 규칙은 기존 대형 파일 끝에 덧붙이지 말고 화면별 파일로 시작합니다.
- `!important`를 새로 추가하려면 기존 cascade로 해결할 수 없는 이유를 코드 주석으로 남깁니다.
- `npm run styles:check`는 대형 CSS 파일의 줄 수와 `!important`가 현재 기준보다 늘어나는 것을 거부합니다.
- 화면별 분리가 끝날 때마다 해당 파일의 예산을 낮춰 부채가 되돌아오지 않게 합니다.
